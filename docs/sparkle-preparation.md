# Sparkle preparation for macOS updates

This unreleased source prepares an exact Sparkle framework and an app-owned manual information check. Default public configuration and reviewed native policy are absent, so the application loads no framework and starts no Sparkle check. Installation has no executable route: no Install choice, package download, installer continuation, document close or relaunch is permitted. Even complete stable-release public feed/key/publisher/native pins cannot enable application startup: the source gate remains disabled until safe native termination, installer cancellation and recovery are implemented and verified. No key is generated, imported, exported or stored by these tools. Prepared source and tests are not native execution evidence.

The proposed stable feed is **https://peerbrush.com/updates/macos/stable/appcast.xml**. This is a proposed, unpublished location, not an available update service or download. Putting the URL in this document does not configure `SUFeedURL`, deploy a feed or authorize its publication.

## Exact dependency and platform boundary

The pin is Sparkle **2.10.0**, official source commit `eef1a539a373c1f1a320624b1130fc5de7b2e100`. Its [official Package.swift](https://github.com/sparkle-project/Sparkle/blob/eef1a539a373c1f1a320624b1130fc5de7b2e100/Package.swift) selects `Sparkle-for-Swift-Package-Manager.zip` with SHA-256 `17e28312b8e18ab7cdbbe09a6fb28cc55a5479ec6c371dbc07cdecd2a14fd959`. The archive verified during preparation is 10,193,895 bytes. The [source release](https://github.com/sparkle-project/Sparkle/releases/tag/2.10.0) and complete upstream/external license notice are recorded in `packaging/sparkle/`; the GPL license of PeerBrush is unchanged. A changed or republished upstream asset fails the committed hash pin.

Sparkle 2.10.0 requires macOS 12 or later. The disabled core application retains macOS 11 support. Both preparation and the native probe reject unsupported systems before loading framework code. The application reports updater unavailability on macOS 11 and never loads Sparkle there. Its source-defined dormant bundle preserves core macOS 11 support; real macOS 11 and supported macOS 12+ launch acceptance remain pending.

The reviewed framework inventory contains **151 entries, 9 exact symlinks and 5 code objects**. It includes the original framework binary, Autoupdate tool, Updater.app and the Installer/Downloader XPC services, plus headers, resources, localization and signature seals. XPC services stay inside their original framework layout and are not enabled. The pin records every regular file's bytes/hash/mode, every directory's mode and every exact relative link target. Unexpected paths, changed bytes/modes, hard links, special files or escaping/dangling links fail. No prefix wildcard is added to any release or signing allowlist.

## Offline staging and native component check

Obtain the public official archive separately; the preparation script performs no download. Select a fresh output outside the checkout. On macOS 12+:

```sh
python3 -B scripts/prepare_sparkle.py \
  --archive /absolute/downloads/Sparkle-for-Swift-Package-Manager.zip \
  --verify-only
python3 -B scripts/prepare_sparkle.py \
  --archive /absolute/downloads/Sparkle-for-Swift-Package-Manager.zip \
  --output /absolute/private/sparkle-preparation-r1
cargo run --locked --example sparkle_preparation -- \
  /absolute/private/sparkle-preparation-r1/Sparkle.framework
```

Archive-only verification is portable and does not load code. Staging checks the complete official archive checksum and exact selected inventory before writing, rejects every registered source checkout/worktree, creates a private immutable directory, copies the complete upstream license and emits a receipt with `release_ready:false`, updater not started and feed/key unconfigured. Existing outputs are never replaced. Failed external work remains for inspection; choose a fresh directory after resolving the cause. Keep receipts and framework/build output outside public source and artifacts.

The explicit native probe rechecks the compiled file/link/hash/mode pin and license before loading code. It uses macOS CommonCrypto for SHA-256 and verifies the five exact nested code objects with native `codesign --verify --strict`. The upstream signatures are ad hoc; this proves integrity of the selected preparation inputs, not PeerBrush Developer ID signing or notarization. It then loads the verified framework through NSBundle and constructs [SPUUpdater](https://github.com/sparkle-project/Sparkle/blob/eef1a539a373c1f1a320624b1130fc5de7b2e100/Sparkle/SPUUpdater.h) with the shared app-owned user driver and weak delegate, without calling `startUpdater`. The component owner retains updater, delegate, driver and framework in that order. Native selector assertions cover disabled checks, relaunch/permission vetoes, exactly-once check cancellation/Dismiss and zero installer invocation. The component invokes no network check, signing operation, installer helper or key tool.

The native byte/signature verifier's scope is the pinned framework and license. The Python preparation script enforces external paths, private output permissions and the exact disabled receipt; the native byte verifier does not authenticate that receipt or assert its parent directory's ownership/privacy. Run the staging tool first for the native CI/component workflow.

Sparkle 2.10.0 exposes no public started-state property: its [updater implementation](https://github.com/sparkle-project/Sparkle/blob/eef1a539a373c1f1a320624b1130fc5de7b2e100/Sparkle/SPUUpdater.m) keeps that state private and enables checking after successful start. The unstarted probe checks `canCheckForUpdates=false`; that property alone cannot prove that an arbitrary updater is stopped or no installation is pending. The prepared manual application route below contains native start/check wiring, but its entry, control and verification-completion path now keep startup disabled independently of public configuration.

CI downloads only the hash-pinned public framework, stages it under the runner's temporary directory and runs the native component check on macOS 26. It keeps private preparation receipts separate; new unsigned application candidates contain the exact dormant framework and full notice, with release readiness still false. Portable synthetic tests cover input hashes, path/type/mode/link tampering, unsupported OS, output safety and disabled immutable receipts; Unix CI additionally exercises actual filesystem links and hard-link rejection. Native Rust tests check platform SHA-256 vectors and public configuration guards. Local Windows verification cannot establish that the macOS bridge compiles or runs; native CI and real installed acceptance must be recorded separately.

## Supported handoff and recovery boundary

The exact pinned [Ready user-driver contract](https://github.com/sparkle-project/Sparkle/blob/eef1a539a373c1f1a320624b1130fc5de7b2e100/Sparkle/SPUUserDriver.h#L194-L253) permits Install, Dismiss and Skip. At Ready, Skip requests cancellation of this prepared installation rather than permanently skipping the version. It is not a cancellation acknowledgement. The [UI/core path](https://github.com/sparkle-project/Sparkle/blob/eef1a539a373c1f1a320624b1130fc5de7b2e100/Sparkle/SPUCoreBasedUpdateDriver.m#L274-L286) dispatches the choice to the installer driver. Its [cancelUpdate implementation](https://github.com/sparkle-project/Sparkle/blob/eef1a539a373c1f1a320624b1130fc5de7b2e100/Sparkle/SPUInstallerDriver.m#L529-L547) marks itself aborted, sends the cancellation message, and immediately aborts the updater cycle. That cycle can finish before the helper handles the request. The [helper cancellation and exit paths](https://github.com/sparkle-project/Sparkle/blob/eef1a539a373c1f1a320624b1130fc5de7b2e100/Autoupdate/AppInstaller.m#L650-L653) asynchronously clean up and exit without a public cancellation acknowledgement. Connection invalidation is suppressed as an updater error once its driver is marked aborted. Skip, abort, cycle finish or a status probe therefore cannot establish the helper's authenticated exit or release the protective Quit hold.

Final replacement occurs after target termination. The installed/relaunched callback is available only when the updater process survives; an updater owned by PeerBrush normally dies with the app. The pinned [plain installer](https://github.com/sparkle-project/Sparkle/blob/eef1a539a373c1f1a320624b1130fc5de7b2e100/Autoupdate/SUPlainInstaller.m#L221-L300) tries atomic exchange and falls back to moving old and new bundles. If the final move fails, restoring the old bundle is attempted with its error ignored. Cleanup can remove those temporary bundles, including after final-install failure. This is not a durable last-working-app rollback guarantee. No private helper IPC or process-control workaround is used.

PeerBrush's `finish_update_exit` already atomically checks the complete saved source set, live reservations and project/workspace operations, then closes engines and releases file ownership. It has no rollback-to-editable-workspace operation. Existing document recovery preserves dirty PSD versions; it does not capture the installed app or an update outcome. The settings migration backup preserves initial legacy input, not each pre-update current profile. These existing features must not be presented as durable update recovery. A trustworthy handoff outcome/cancellation boundary and current app/profile recovery must be implemented and verified before connecting a continuation to that irreversible final close. No speculative success branch, installer continuation, `finish_update_exit` call or activation is added by this audit. Native startup, download and installation remain unavailable independently of public feed/key/native-policy setup; installed acceptance is still required.
